# 信息确认与提问

目标是主动消除会改变处理结果的不确定性，而不是让用户反复授权已确定的步骤。先检查已有文件与会话，再提问；按用户的语言和经验解释必要术语。

## 分阶段提问

1. **开场**：工作目录、目标、本轮任务范围。用户已给路径或让从目录识别时先读目录。
2. **读完清单**：只问文件不能确定、但影响分组和校准的项目。显示“已核实／推测／待确认”，附证据和影响。
3. **发现缺场**：先问库的位置；没有库则询问补拍能力和保存位置，提出建库计划。
4. **执行前**：简述将用哪些场、哪些不使用、工作和输出目录。关键问题尚未回答时等待其相关步骤；继续清点、核对其他组或准备脚本。
5. **后期**：结合实际候选询问构图和审美。无意向时给温和起点，不擅自裁掉天体、永久拉伸原件或强制外部编辑器。

每轮通常1–3个相关问题。提问应自包含，例如“这组120秒与300秒的通光量不同：拍后两张时是否已经换滤镜？这会决定它们加入哪组。”不要让用户从一堆实现术语中猜答案。

## 哪些不确定性需要问

| 发现的问题 | 先从哪里找证据 | 问什么／为什么 |
|---|---|---|
| 工作路径不可访问 | 路径、挂载、权限和实际文件列表 | 是本机、移动盘还是网络盘；请确认当前可访问位置。不能把不可见盘当作空库 |
| 文件类别或目标名矛盾 | IMAGETYP、OBJECT、坐标/WCS、时间、实际星场 | 是否旧任务标签、换目标、换滤镜或混入试拍；确认后建立处理清单，原件不搬动 |
| 同型号多台相机 | 设备标识、采集日志、用户分组 | 是否同一台机身；缺设备标识时不能跨机共用暗场 |
| Gain/ISO、Offset、读出模式未知 | FITS/EXIF、驱动或采集日志 | 具体拍摄设置；不要把界面Offset数值当作图像ADU |
| 冷却和温度未知 | CCD-TEMP、SET-TEMP、采集时间 | 是否控温、实测温度是否稳定，能否重现；环境温度不能替代传感器温度 |
| 已校准/已拉伸状态不明 | 数据维度、CFA、HISTORY、软件导出方式 | 是原始帧、机内处理输出还是最终叠加；避免重复减场和二次拉伸 |
| 平场匹配不明 | 滤镜、镜头、相机朝向、焦点、灰尘图样 | 是否拆装/旋转/清洁，能否重现；子午线翻转不自动等于相机相对镜筒旋转 |
| Master缺来源 | 原始清单、制作日志、STACKCNT、DATE和HISTORY | 是否已减偏置、怎样归一化；先重建来源，不能凭文件名猜 |
| 窄带滤镜信息缺失 | FILTER、设备记录、厂家规格 | 确认型号、通带和带宽；缺信息时不伪造窄带SPCC参数 |
| 外部编辑返回改变几何 | 尺寸、方向、像素结构/WCS | 是否裁切、旋转、缩放或变形；需要同步变换或重新配准 |
| 多夜/混合设备的合并目的不清 | 曝光组、FOV、滤镜、目标重叠 | 普通叠加、HDR、马赛克还是独立RGB星点；不能一概拼入同一序列 |

可从文件可靠判断的值无需再次询问。可逆的显示预览、质量分析与已有授权内的例行步骤继续进行。用户已明确选择缺场继续、保留全幅或某个配色时记录并沿用。

## 用户不知道时

说明如何找到所需信息，例如拍摄软件的相机设置、设备型号或原始文件头；提供有限可行路线。不能重现关键条件时，明确风险，让用户选择补拍、等待或有说明的降级流程。对于不影响当前工作的可选风格问题，可先提供预览；对于影响校准正确性的缺项，等待回答或形成经用户接受的替代路线。

## 运行环境

先确认Siril版本、系统和当前可用接口。使用实际路径查找程序、Python、已装脚本、模型、GPU和星表，不硬编码开发者机器的位置。没有直接访问用户机器的工具时说明限制并给出可执行手工步骤，不声称已执行。

给出保守磁盘与内存估算。单张未压缩32位RGB数据约为 `宽×高×3×4` 字节，校准/配准序列、拒绝图、模型缓存与多个检查点会另外占用空间。资源不足时与用户选择分批、FITS序列格式、降低并行数或另一个工作盘。
